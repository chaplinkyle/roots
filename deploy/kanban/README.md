# Deploy Roots Kanban on AWS

This deployment creates new, application-specific resources. It uses one 0.5-vCPU/1-GiB Fargate task, RDS PostgreSQL 16.13 on `db.t4g.micro` with 20 GiB encrypted storage (up to 100 GiB autoscaling), seven-day backups, and a public HTTPS Application Load Balancer. The database has no public address or internet route. Only the application security group can reach PostgreSQL. The app accepts incoming traffic only from its load balancer.

Application tasks have public addresses for outbound ECR, logging, and secret access, avoiding a NAT gateway. This does not open their application port to the internet. Database connections use `sslmode=verify-full` with the AWS RDS CA bundle. Secrets are generated by Secrets Manager and injected by ECS; none are baked into the image, written into this repository, or printed by the deployer.

The deployment incurs ongoing AWS charges for compute, RDS, the load balancer, IPv4 addresses, storage, logs, and secrets. Sizes are intended for a small pilot. There is no automatic teardown.

## Deploy

Required: AWS credentials for the target account, Java 25+, Maven, Docker, Chrome for the application tests, a Route 53 zone, and an issued ACM certificate in the target region covering an unused subdomain. The script rejects an unexpected account, an unrelated existing stack, and an existing DNS record on first deployment.

First run the PostgreSQL verifier described in [the application README](../../examples/kanban/README.md), then:

```powershell
python deploy/kanban/deploy.py `
  --profile <aws-profile> `
  --account <12-digit-account-id> `
  --region us-east-1 `
  --domain <unused-subdomain.example.com> `
  --zone-id <route53-zone-id> `
  --certificate <issued-acm-certificate-arn> `
  --maven <absolute-path-to-mvn.cmd>
```

The deployer tests and builds the JAR and container, creates the infrastructure with zero application tasks, pushes an immutable image tag, runs `--migrate` in a dedicated ECS task, and enables the service only after that task exits successfully. It then verifies public HTTPS database readiness. Subsequent runs build a new immutable tag, migrate before replacing the running service, and preserve the database. Migrations must remain compatible with the previous running application until the service is replaced.

The output includes the application URL, the `admin` username, and the Secrets Manager ARN containing its generated password. Retrieve the password privately in the AWS console. Then verify sign-in, create, move, edit, reload, and archive at the deployed URL. Public readiness alone does not establish browser-flow correctness.

The app uses local bootstrap authentication initially. OIDC is supported by the application, but adding its settings and secret to the task definition is an explicit deployment customization; it is not enabled by this template.

## Operations

- `/actuator/health/readiness` checks Roots and the actual application database table. Details are not exposed publicly.
- The stack's `Logs` output identifies its CloudWatch log group. Logs are retained for 30 days.
- ALB affinity is enabled. The service is intentionally limited to one task and uses stop-before-start updates; expect a short interruption and sign-in after deployment. Saved data remains in RDS.
- RDS deletion protection is enabled. Stack removal requires deliberately disabling it first; database deletion then creates a final snapshot. ECR, secrets, and logs are retained. Review retained resources and costs before teardown.
- Do not rotate the database secret alone: update the RDS password to match, then replace the application task. Replace the app task after rotating the login secret as well. Existing browser sessions expire after 30 minutes of inactivity; revoke access through the identity provider when using OIDC.
- Pin reviewed base-image digests using Docker build arguments `BUILD_IMAGE` and `RUNTIME_IMAGE` in a release process. ECR image tags are immutable. The initial runtime and migration user is the dedicated database owner; split those roles before expanding beyond the pilot.
